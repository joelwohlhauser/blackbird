# Sidequests

While working you'll notice things that aren't part of the current change: a bug next door, a workaround that should go, an idea. Never fold them into the current pull request quietly.

Note each one as you find it, with one line on what it is and why it matters. Then list them at two moments, in the proposal and in the Ready report, each with your recommendation:

- **Fix in this pull request:** only when it is tiny and in the code you are already changing.
- **Start now in a separate thread:** with `thread_launch` in its own worktree, when it's urgent or blocks this work.
- **File it:** a backlog issue in the tracker (see `issues.md`). This is the default.

The user picks per item. Whatever they don't pick gets filed when the work is handed back. Skip the list when there is nothing.
